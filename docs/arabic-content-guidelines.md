# دليل الصياغة العربية لمنصة سيرو كاش

## النهج التحريري

تعتمد الواجهة لغة عربية فصحى مؤسسية، دقيقة ومباشرة. المقصود بالصياغة الرسمية استخدام المصطلحات الصحيحة، وليس الإطالة أو توظيف تعبيرات أكاديمية يصعب فهمها.

- تُسمّى الوظيفة أو الإجراء بوضوح: «إنشاء حساب»، «تقديم طلب سحب»، «مراجعة بيانات الطلب».
- تُعرض التعليمات بصياغة محايدة، مثل «يُرجى إدخال...» و«يتطلّب هذا الإجراء...».
- تُحذف الاستعارات والوعود المطلقة، مثل «حكايتك المالية» و«حرية بلا حدود» و«أمان مضمون».
- لا توحي النصوص باعتماد تنظيمي أو ترخيص أو ضمان للأموال دون مستندات تثبت ذلك.
- تُوضَّح حدود الإصدار التجريبي وعدم تنفيذ عمليات بأموال فعلية.
- لا يُعرض نجاح تسوية مالية لمجرد تسجيل طلب. تختلف «تم تسجيل الطلب» عن «اكتمل التحويل».
- لا يُذكر مزوّد البريد في الواجهة أو رسائل الخطأ الموجّهة للمستخدم.

## المصطلحات المعتمدة

| المفهوم | المصطلح |
|---|---|
| Account registration | إنشاء حساب |
| Sign in | تسجيل الدخول |
| Email verification | التحقق من البريد الإلكتروني |
| Identity verification / KYC | التحقق من الهوية؛ إجراء مستقل عن تأكيد البريد |
| Password | كلمة المرور |
| PIN | رمز التعريف الشخصي |
| Passkey | مفتاح مرور |
| Device verification | التحقق من الجهاز باستخدام البصمة أو رمز القفل؛ لا تُضمن بصمة الإصبع وحدها |
| Recipient | المستفيد |
| Internal transfer | تحويل داخلي |
| Withdrawal request | طلب سحب |
| Available balance | الرصيد المتاح |
| Reference | الرقم المرجعي |
| Double-entry ledger | دفتر أستاذ بنظام القيد المزدوج |
| QR | رمز الاستجابة السريعة (QR) عند أول تعريف |

## الإشعارات والأخطاء

يُذكر سبب التعذّر بقدر المعلومات المتاحة، مع توضيح الإجراء التالي دون كشف بيانات حساسة. يجب تجنّب تأكيد ملكية بريد أو حساب في رسائل تسجيل الدخول، وعدم تحويل فشل تقني إلى ادّعاء بنجاح العملية.

هذه إرشادات تحريرية للواجهة، وليست مراجعة قانونية أو شهادة امتثال مالي.
