# تقرير مراجعة أمنية معمّقة — SiroCash

**التاريخ: 31 أكتوبر 2026**
**الحكم: اجتياز اختبارات محلية، وليس تصريح تشغيل مالي حي.**

## نطاق الفحص
مراجعة يدوية للمسارات الحساسة: تخصيص عناوين الإيداع، أدلة الإيداع والتقييم، موافقات الجهاز، عروض السحب والحجز، التوقيع وحفظ المعاملات، إذن الموارد والمصروفات، الإرسال والتأكيد النهائي والتسوية. شملت المراجعة قيود قاعدة البيانات، صلاحيات التطبيق، منع كشف الأخطاء، مصدر الطلبات، إعداد فحص المفاتيح، وحدود أدلة RPC. لا يمثل ذلك تدقيقًا مستقلًا أو إثباتًا لغياب جميع العيوب.

## نتائج جديدة عولجت

### 1. حالة نهائية دون سجل دليل مطابق
كان قيد التسوية يربطها بحالة سجل الدفع ومرجعه، لكنه لم يشترط بنفسه وجود دليل نهائي مطابق عند تغيير حالة السجل إلى CONFIRMED. صلاحيات التطبيق المعتادة لا تسمح بتلك الكتابة؛ الخطر دفاعي ضمن حدود عامل مالي ذي صلاحيات كتابة، وليس مسارًا عامًا مكشوفًا للمستخدم.

أضيف ترحيل محضّر يشترط سجل تأكيد مطابقًا للشبكة ومعرّف المعاملة والمرسل والمستفيد والمبلغ، ويمنع التسوية بلا سجل دليل. مُنع تحويل السحب الموقّع إلى REJECTED/FAILED بمجرد علامة رفض، لأن إثبات فشل التنفيذ وتكاليفه لم يكتمل بعد. تبقى الأموال محجوزة بدل تحريرها على أساس غامض.

اختبارات الرجوع ترفض تغيير الحالة دون دليل أو الرفض المباشر. لم تعد تختصر اختبار فرادة nonce بوضع CONFIRMED مباشرة؛ تمرّ أولًا عبر تأكيد اصطناعي مطابق والتسوية الفعلية. هذا القيد لا يحمي من مالك قاعدة بيانات يزوّر الأدلة أو يعطّل المشغلات؛ مصدر الأدلة وصلاحيات العامل ما زالا حدًا أمنيًا حاسمًا.

### 2. انتهاء صلاحية إذن الإرسال أثناء الانتظار
قد ينتهي إذن الموارد بعد بدء فحصه وأثناء الانتظار/الحفظ. استُبدلت قراءة وقت بدء التعليمة بساعة SQL الجارية في فحوص حداثة الموارد والإذن، وأضيف فحص انتهاء آخر بعد اكتمال الحفظ وقبل استدعاء المرسل.

عند انتهاء الإذن لا تُستدعى الشبكة، وتبقى المحاولة UNKNOWN والحجز قائمًا. لا تُعاد المحاولة تلقائيًا. أضيف اختبار يؤخّر عودة المعاملة إلى ما بعد انتهاء الإذن ويؤكد عدم استدعاء المزوّد. تزامن ساعة الخادم/قاعدة البيانات يظل متطلب تشغيل؛ لا توجد هنا معايرة ساعات إنتاجية.

### 3. التحقق الصارم من حالة حساب TRON
الجاهزية تتطلب `accountActive === true`، وليس أي قيمة تبدو صحيحة مثل نص غير فارغ. أضيف اختبار يرفض الحالة النصية مع تحقق الموارد العددية.

## نتائج التحقق في هذه الجولة
- `npm audit --audit-level=low`: لا ثغرات معروفة وفق سجل npm وقت الفحص. ليس ضمانًا أمنيًا شاملًا.
- `npm test`: نجحت مجموعة الاختبارات الكاملة، بما فيها التوقيع المحلي الحقيقي لمفاتيح اختبار علنية، قاعدة PGlite المحلية، اختبارات الفشل والرجوع والحدود الأمنية.
- `npm run build`: نجح.
- `npm run lint` و`git diff --check`: نجحا.
- لم تظهر استدعاءات وظائف توقيع/إرسال الدفع أو التجميع الخاصة داخل مجلد مسارات `app` في فحص الربط النصي. هذا ليس بديلًا عن تحليل تدفق بيانات شامل.
- بقيت أخطاء الخادم منقّحة، وأسرار الاختبار/المحفظة غير مطبوعة. لم تُفك مفاتيح الإنتاج ولم يُشغّل فحص مطابقتها عليها.

## ما لا يزال يمنع تشغيل أموال العملاء
1. مطابقة مفاتيح الإنتاج داخل تنفيذ معزول ومراجع، وخطة نسخ واسترداد فعلية. حفظ الأسرار وحده لا يثبت صحتها.
2. مراقبو الشبكة والمحاكاة الفعلية ومصدر تسعير معتمد وصلاحيات تشغيل ضيقة. الأدلة الاصطناعية ليست بيانات شبكة حقيقية.
3. شراء الطاقة: حجز الميزانية قبل الشراء، طلب مدفوع ذو هوية ثابتة، متابعة الطلبات الغامضة، والتحقق المستقل من التفويض. تجهيز طلب محلي لا يعني شراءً أو وصولًا.
4. استكمال توحيد مصروفات التجميع والسحب وكل مستهلكي nonce، والتعافي من التحويلات الفاشلة والطلبات العالقة وإعادة التنظيم العميقة.
5. اختبارات PostgreSQL مستقلة الاتصالات؛ PGlite يسلسل المعاملات ولا يثبت سلوك التزامن في الإنتاج.
6. تجربة أجهزة حقيقية لتأكيد العملية واسترداد/إلغاء وسائل الدخول، وربط واجهة العرض والتأكيد بالخدمات المحمية.
7. مراجعة الترحيلات وتطبيقها بصلاحيات مخصصة، ثم تجربة مالية صغيرة وموافق عليها صراحةً. كل الترحيلات الجديدة في هذه الجولة محضّرة فقط.

## أفعال لم تُنفَّذ
لا تعديل لأسرار الإنتاج أو بوابات تفعيله، لا نشر إنتاجي، لا ترحيل قاعدة إنتاج، لا شراء موارد، لا توقيع بمفاتيح المالك ولا بث معاملات. يظل التوقيع الحي معطّلًا وفق آخر تحقق منفصل من إعداداته. لم يُجرَ اتصال تحقّق جديد بلوحة الإنتاج في هذه الجولة.
