## Receipt verification added

`lib/tron-deposit-verification.ts` validates a trusted TRON USDT Transfer receipt log against the expected assigned address, canonical block hash and solid height. It checks successful execution, exact official USDT contract (TRON mainnet), padded topics, positive bounded uint256 amounts and a txId/logIndex event identity. Amounts remain USDT base units, NOT implicit USD credit.

This is a pure verifier using SYNTHETIC evidence in tests, NOT an authenticated RPC watcher. Its caller must independently fetch transaction inclusion/canonical block/solid height from trusted mainnet infrastructure, normalize raw TransactionInfo result semantics explicitly and reject unknown status. Never translate a missing result into SUCCESS. Hash/height fields passed by a client are not proof. No route accepts this input, no deposit was credited, and no watcher was deployed. Persist event identity with a unique database constraint and atomically bind approved valuation/ledger posting before ingestion goes live. Event index is the original receipt-log index, not the filtered Transfer position. Historical canonical checks, node disagreement/reorg alarms, replay/checkpoints and restricted-role testing remain necessary.
