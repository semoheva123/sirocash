# حجز ميزانية الطاقة قبل الشراء — مرحلة خاصة غير مفعلة

> تحديث تركيب الإنتاج 2026-10-31: بتفويض المالك طُبّق ترحيل ميزانية الطاقة فعليًا، وأصبح سجل Prisma 32 ترحيلًا. تحقق كتالوج الإنتاج من RLS وحجب وصول API/runtime للجدولين الجديدين، والسياسة بقيت disabled. فاحص البناء توسّع إلى 22 جدولًا وخمسة triggers وأصبح إلزاميًا في production. نُشر التطبيق بالمراجعة ac8a8a4 بنجاح READY/PROMOTED في النشر dpl_8wBWWpmBapbyv7a9EKWmtY4s9avB؛ نجح فحص الجداول الـ22 عبر اتصال الإنتاج الفعلي أثناء البناء. لا يعني هذا اكتمال أو تفعيل شراء الطاقة أو التشغيل المالي. انظر [دليل النشر](production-rollout-2026-10-31.md).

## المنفذ في هذه الجولة

`lib/energy-purchase.ts` يربط طلبات الطاقة المشتركة للسحب والتجميع بميزانية واحدة قبل أي استدعاء خارجي:

- قفل صف السياسة قبل جمع الحجوزات لمنع تجاوز ميزانية المزود بين طلبين مستقلين.
- سقف لكل أمر وسقف إجمالي للمبالغ المحجوزة بوحدة SUN، مع رفض السعر الذي يتجاوز سقف النية.
- مطابقة بصمة النية وعنوان المستفيد من الطاقة والكمية والمدة بعرض محدد صلاحيته بحد أقصى 60 ثانية، وفق ساعة PostgreSQL.
- فحص استمرار حجز السحب؛ أو جاهزية حساب الإيداع وخزنته وغياب sweep موقّع غير محسوم. المستفيد من الطاقة هو عنوان التشغيل للسحب، وعنوان الإيداع للتجميع، وليس عنوان التحويل النهائي.
- تسجيل UNKNOWN دائم وميزانية محجوزة وتغيير النية إلى UNCERTAIN **قبل** استدعاء المزود. قفل العملية/المصدر يسبق قفل النية، مثل مسار تجهيز النية.
- إعادة الاستدعاء لنفس النية تعيد الحالة ولا ترسل أمرًا ثانيًا، سواء نجح الرد أو انقطع الاتصال أو انتهت المهلة.
- ACKNOWLEDGED يثبت قبول رد يحمل معرّف أمر فقط. لا يحوّل النية إلى DELIVERED ولا يجيز توقيعًا.
- أخطاء المزود لا تعاد إلى المستدعي بمحتواها؛ لا يخرج سوى UNKNOWN عند النتيجة الملتبسة.
- الحجوزات لا تتحرر تلقائيًا، حتى بعد منتصف الليل أو ACK؛ هذا محافظ وقد يوقف مشتريات جديدة حتى تطوير تسوية موثوقة. لا يُستخدم نجاح النقل لإعادة المال أو إعادة الشراء.

ترحيل `20261031200000_energy_purchase_budget` ينشئ جدولين بسياسة disabled وبقيم رفض افتراضية، RLS، وسحب منح PUBLIC/anon/authenticated/sirocash_app حتى مع المنح الافتراضية للاستضافة. قيد فريد يمنع محاولة ثانية لنفس النية، وtrigger يمنع حذف المحاولة أو تعديل ميزانيتها/هويتها أو عكس ACK.

## الاختبارات

`npm run test:energy-purchase` يستخدم PostgreSQL مضمّنًا PGlite مع مزود اصطناعي، ويغطي:

- علم الخدمة والسياسة معطلين، عرض منتهي أو غير مطابق، سقف الأمر والسقف الإجمالي.
- خزنة إيداع معطلة أو sweep قائم؛ سحب لم يعد محجوزًا؛ ومسار سحب ناجح اصطناعيًا.
- rollback بعد إدراج حجز وقبل اكتمال المعاملة، دون استدعاء خارجي أو حجز متروك.
- رفض ميزانية أمر جديد بعد استهلاكها بأوامر مختلفة؛ عدم إعادة الإرسال بعد ACK أو UNKNOWN.
- انقطاع مزود/مهلة/معرف أمر غير صالح؛ immutability وRLS وحجب الوصول.

أضيف الاختبار إلى npm test. نجح npm test كاملًا وnpm run build مجددًا بعد آخر تقوية لمطابقة الأدوار واختبارات rollback والسحب. نجح npm audit بصفر ثغرات معروفة. ليست هذه اختبارات PostgreSQL متعدد الاتصالات ولا تجربة شراء حقيقية.

## الحدود التي لا يجوز تجاوزها

- **طُبّق الترحيل على الإنتاج بتفويض المالك**، وبصمته `5df40961c79f75ac80a735b1ca5f33ba11ce44df1f0943746ac4b01ffd194889`. سجل Prisma الآن 32 ترحيلًا؛ فاحص الجاهزية توسع إلى 22 جدولًا، وخمسة triggers، وخمسة indexes أساسية، مع فحوص رفض SELECT الفعلية على جدولي الشراء الجديدين.
- لا توجد وصلة شراء TronZap حية أو cron أو endpoint لهذا المسار، ولا تفويض نشره؛ `send` حقن خاص للاختبار والتكامل اللاحق فقط. لا يعدّ وجوده تنفيذًا لشراء الطاقة تلقائيًا.
- يجب على محول المزود النهائي فرض حد التكلفة الفعلي، وشمول activation fee وأي مصروفات أخرى. حساب التكلفة محليًا وحده لا يضمن أن المزود لن يخصم أكثر.
- المخطّط الموثوق يجب أن يثبت الرصيد القابل للتجميع، مقدار الطاقة المطلوب، وحالة الحساب وتكلفة التنشيط قبل إنشاء النية وعرض السعر. فحص السجل ليس إثباتًا على السلسلة.
- السقف الإجمالي SUN ليس ميزانية يومية USD، ولا يضمن تقدير الثلاثة دولارات، ولا يغيّر رسوم العميل أو حدود السحب المقررة.
- التسوية واسترداد UNKNOWN وإثبات توصيل الطاقة لم تُنفّذ هنا. لا تُفتح صلاحيات المال العامة ولا يفعّل التوقيع تعويضًا عنها.
- لا تزال المراقبة والبث والجدولة والتسعير واختبارات الاستعادة/الأجهزة الحقيقية عملًا منفصلًا غير مكتمل؛ قرار الإطلاق المالي NO-GO باقٍ.
