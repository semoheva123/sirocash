# Obsidian wallet interface

## Modules

- `app/obsidian.css`: explicit `data-theme="obsidian"` design boundary, Zinc-950 canvas, glass surfaces, cyan primary/USDT accents, violet network accents, responsive bottom navigation, modal entrance animation and reduced-motion/transparency fallbacks. Loaded after the existing layout sheets; it does not rewrite financial state classes or replace route layouts.
- `components/wallet-actions.tsx`: authenticated wallet shortcuts, send/receive dialog state, network/method selection, form fields, owner-bound QR and clipboard interactions. Reuses `DialogFrame` for body scroll locking, Escape dismissal, focus trapping and focus return.
- `components/toast-notice.tsx`: dismissible, timed success/info/error notices, rendered into `document.body` so glass-card stacking/overflow cannot clip them. Clipboard rejection is an error, never a success.
- `lib/wallet-presentation.ts`: pure receive-projection and validated secure-review handoff helpers. No providers, signing, database operations or payment execution.
- `tests/obsidian-wallet.tsx`: owner isolation, missing/malformed address rejection, exact decimal-string handoff, invalid/hostile prefills, truthful copy/disabled behavior contracts and theme wiring.

## Financial and identity semantics

The authoritative ledger is denominated in **USD**, not an assumed equivalent quantity of USDT. The balance remains labeled USD; cyan styling does not convert or relabel it. The send dialog explicitly prepares a **USDT withdrawal** for the existing secure payments screen. Address and amount are prefills only, not approved instructions. The existing server validation, quote, idempotency, device approval, execution flags and current-stream requirements remain in force.

No financial API is called by `WalletActions`. When commands/withdrawals are disabled, the connection is stale, or the owner does not match, submitting the dialog produces an informational availability notice and does not navigate or move funds. With the required existing capabilities and a current owner-bound snapshot, valid details continue to `/payments` for independent secure review; this is not a transaction success confirmation.

The receive dialog defaults to a real assigned USDT address when available. Otherwise it offers the real owner-bound internal account identifier. The internal QR is labeled **not a blockchain address**. The crypto tab only displays an address in the selected network from the current authenticated snapshot; no sample address or QR is fabricated for absent, stale, malformed or foreign-owner data. No address is generated by opening a dialog. QR graphics have accessible titles and retain an opaque white quiet zone.

Copy feedback appears only after a successful clipboard write. An address/network/dialog change invalidates pending clipboard feedback; closing a dialog clears its draft fields. Amounts remain decimal strings and Arabic/Persian digits are normalized for entry, without floating-point conversion in the handoff.

Explicit Obsidian overrides now cover the shared guidance header, rows, labels, values, notes, private page heading and unavailable-service icon/surface across deposit, withdrawal, Sham Cash and mobile top-up. Isolated real ServiceBrief fixtures were checked at 320/390/768/1440px, Arabic/English: 32 layouts without overflow and 32 axe scans without violations. This is visual component evidence, not a production authenticated transaction test. The existing unit suite now checks the shared component and explicit service theme selectors.
