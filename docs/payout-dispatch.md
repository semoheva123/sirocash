# Private payout dispatch worker — gated, fixture-tested

`dispatchSavedPayout` accepts a payout UUID and a trusted server-injected bounded send adapter. It has no installed mainnet adapter, scheduler or public HTTP route and refuses execution unless explicitly enabled by its private caller. No production flag/secret/deployment is changed. Tests use mock adapters only, never a real network send.

A separate reviewed balance/resource/budget authority must first populate `PayoutDispatchApproval`. This implementation does NOT create those approvals, verify live balances/energy delivery, purchase resources or claim a global expense budget. The authority must do those checks and reserve expenses before provisioning a short-lived approval. Its reference, exact TXID, signed-payload SHA256 and maximum native transaction fee are persisted privately with SQL-clock validity. Neither a customer boolean nor mere provider quote is an approval.

The worker locks quote, operation and signed payout in the existing order; checks ownership binding, net amount/recipient, saved signature/chain/token/calldata, BSC nonce or TRON expiry, and maximum signed native fee against the approval. Before any adapter call it atomically consumes approval, inserts a unique UNKNOWN attempt/claim and marks the payout BROADCAST_UNKNOWN. That commit must succeed before send. A crash even before actual network submission deliberately remains unknown: never infer failure or release the hold.

The adapter receives only the saved payload/TXID/network and AbortSignal; the deadline defaults to 10 seconds (100ms–30s configurable privately). Its matching TXID acknowledgement changes only attempt status, NOT payout finality or ledger state. Timeout, exception, mismatched TXID or lost database acknowledgement remain UNKNOWN. Provider text/secrets are not returned. An adapter may complete after timeout, so attempts are not retried automatically. Every repeat returns durable status without another send or signature. A later recovery worker must read back the chain and, only when safe, explicitly rebroadcast identical bytes; that recovery worker is not yet implemented.

Migration `20261031140000_payout_dispatch` is prepared only, with RLS and no normal-app grants. No production migrations were applied. Private authority access is not proof of genuine resources: live authority, unified budgets, independent provider verification, live receipt observation/normalization and resource-budget verification remain launch gates. Private success-only receipt/amount binding and atomic final settlement are now implemented in `payout-confirmation.ts`, tested synthetically, not activated. This is dispatch orchestration, not the completed live withdrawal service.

Fixture tests cover no approval/no send, fee cap rejection, claim visible before adapter invocation, identical bytes, acknowledgement without finality, request/body-equivalent adapter timeout, no-resend retry, and preserved holds. Full real PostgreSQL multi-session contention and funded failure drills remain required.
