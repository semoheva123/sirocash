# تجهيز الإنتاج — نتائج فعلية وحدود التشغيل

التاريخ: 2026-10-31.

> تحديث بعد إضافة المالك المفتاح: نجح الفحص الثالث `dpl_2DQGu3kGHB1qgwSMu8Go5PD43ajQ` عند المراجعة `da00441`: جميع المراحل TRC20_CUSTODY وBEP20_DEPOSIT وBEP20_OPERATING أعادت MATCHED_NO_SIGNING. أُغلق نقص مفتاح تشغيل BEP20، وبقي التوقيع معطلًا؛ خرج الفحص عمدًا 1 لمنع النشر. أُعيد أمر البناء إلى npm run build مع npm ci بنجاح. التفاصيل أدناه عن غياب المفتاح تصف الفحصين السابقين، لا الحالة الحالية. لا يغيّر ذلك NO-GO لبقية نواقص التشغيل.

## نتائج جديدة مثبتة داخل بيئة الإنتاج

لم تُسحب المفاتيح أو DATABASE_URL إلى المحادثة أو بيئة التطوير. شُغّل فحصان خاصان داخل بناء Vercel بإعدادات production، مع توقيع معطل. السكربت يفشل عمدًا بعد طباعة الحالات الآمنة، حتى لا ينشر endpoint أو يروّج نسخة اختبار إلى الموقع.

| الفحص | النتيجة |
|---|---|
| مفتاح تشغيل TRON مقابل عنوان التشغيل المحدد | MATCHED_NO_SIGNING |
| XPRV/XPUB لحساب إيداع TRON وأول عنوان THici… | MATCHED_NO_SIGNING |
| XPRV/XPUB لحساب إيداع BEP20 وأول عنوان 0x6CD3… | MATCHED_NO_SIGNING |
| مفتاح تشغيل BEP20 | MATCHED_NO_SIGNING في الفحص الثالث |
| اتصال التطبيق الفعلي بقاعدة الإنتاج | TLS موثّق ودور sirocash_app محدود |
| الجداول المالية العشرون عبر الاتصال الفعلي | VERIFIED |
| RLS وعزل anon/authenticated وحجب صلاحيات المال عن runtime | VERIFIED |
| وجود أربعة triggers وخمسة unique indexes أساسية | VERIFIED |
| SELECT LIMIT 0 الفعلية على ثلاث جداول مال | رفض الصلاحيات المتوقع تحقق |
| SELECT LIMIT 0 على جداول التحقق الدائم الثلاثة | نجاح دون قراءة سجلات |

فحص المخطط تم في معاملة READ ONLY. لا يقرأ سجلات العملاء أو سجل Prisma الإداري، ولا يُغيّر أية عضوية دور أو صلاحية. هذا يُغلق فجوة الاختبار السابقة التي تعذر فيها SET ROLE عبر اتصال إدارة Supabase: الآن أُجري الفحص باتصال التطبيق الحقيقي نفسه.

فحوص مطابقة الحسابات تثبت correspondence للمفاتيح وأول عنوان فقط، ولا تثبت الأصل hardened أو أن حسابي الشبكتين من العبارة نفسها، ولا سلامة النسخة الاحتياطية أو عدم تسرب عبارة الاسترداد سابقًا.

- الفحص الأول: `dpl_2fMXh9Aco2tZ8RTwNY8ZcMnVQvaY`، مراجعة `d45ba89`؛ نجح db:verify ثم عُرضت نتائج custody الآمنة وانتهى البناء عمدًا بخروج 1.
- الفحص الثاني: `dpl_8BLoVti3zBo3PydXsGj459aFuxZX`، مراجعة `61a28f3`؛ ظهر `Financial schema preflight: {"status":"VERIFIED","tables":20,"rls":true,"publicAccess":false,"runtimeFinancialAccess":false,"authenticationStorage":true,"guardsPresent":true,"zeroRowQueries":true}` ثم نتائج custody نفسها.
- عُدّل Build Command مؤقتًا لكل فحص، ثم أُعيد فعليًا إلى `npm run build`؛ Install Command بقي `npm ci`. رُفضت محاولة أمر طويل قبل التنفيذ، فلم تُغيّر الإعدادات. منع النظام إعادة طلب الاستعادة الثاني المتطابق؛ نُفّذت الاستعادة بطلب جديد يؤكد أيضًا Install Command الموجود، ونجحت.
- قائمة READY production بعد الفحصين أكدت بقاء `dpl_CbLpXmRG95f8WB6zKBWkwddEnTXc` / `ed96a6ff…` دون استبدال. حالة ERROR للفحصين متوقعة لتصميم no-deployment وليست إثبات تعطل الموقع.
- لم يتغير أي secret أو علم توقيع، ولم تُستدعَ خدمات توقيع/بث/شراء طاقة أو إرسال بريد.

## الأدوات الخاصة المضافة

- `npm run custody:probe`: production فقط والتوقيع يجب أن يساوي false؛ يفحص المراحل الثلاث مستقلة ولا يطبع مدخلات أو قيم مفاتيح؛ **يخرج دائمًا 1** ولا يدخل npm build أو cron أو API.
- `npm run db:financial-check`: اختياري عبر `SIRO_FINANCIAL_SCHEMA_CHECK=true`، production والتوقيع معطل؛ فحص كتالوج وصلاحيات صفري السجلات داخل READ ONLY، ثم ROLLBACK.
- اختبارات `test:custody-probe`: رفض preview والتوقيع المفعّل، إخفاء القيم غير الصالحة، جميع المراحل، والخروج غير القابل للنشر.
- اختبارات `test:financial-isolation`: منح افتراضية مشابهة للاستضافة، الجداول العشرون، فحص فعلي بدور التطبيق محليًا، ورفض دور مفرط الصلاحية أو وصول مالي غير مقصود أو غياب قيد uniqueness.
- نجح npm test كاملًا وnpm run build وnpm audit بصفر ثغرات معروفة بعد الإضافات. الاختبارات المحلية لا تعادل funded drills أو تزامن اتصالات PostgreSQL مستقلة.

## نقص سابق أُغلق بالفحص الثالث

المتغير `SIRO_BEP20_OPERATING_PRIVATE_KEY` غائب في البيئة التي نُفّذ فيها الفحص. المطلوب هو مفتاح عنوان التشغيل:

`0x31d88dEc98de331caEA32028ae9b6995B82e8Bdb`

يضيفه المالك مباشرةً كسر production فقط، دون نقله إلى الدردشة، ودون استبداله بمفتاح حساب الإيداع أو Root Key أو عبارة استرداد. لا يمكن اشتقاق حساب التشغيل المختلف من XPUB، ولا نفترض أن مفتاح TRON هو مفتاح BSC. بعد الإضافة يُعاد الفحص الخاص قبل استخدامه.

## ما لا يزال يمنع الإطلاق المالي

هذه الجولة لا تكمل كل الخدمات المالية. ما زالت الأجزاء التالية عملًا برمجيًا/تشغيليًا مفتوحًا، لا مجرد أعلام يجب تفعيلها:

1. سلطة تسعير موثوقة وإصدار أوامر مالية حيّة مربوطة بالموافقة والقيد.
2. مراقبو TRON/BSC النهائيون، نقاط التقدم وإعادة التنظيم، ومحولات البث والجدولة.
3. شراء الطاقة، والميزانية المشتركة **قبل** الشراء، والتحقق من التسليم، والتعافي من طلب/معاملة مجهولة النتيجة دون تكرار.
4. تحديد صلاحيات الخدمات المالية الضيقة؛ لا تُمنح sirocash_app صلاحيات دفتر الأموال دفعة واحدة.
5. تجارب جهاز حقيقي، وتزامن مستقل، واستعادة نسخ احتياطية، ومراقبة ومطابقة وتنبيهات.
6. بريد نطاق موثّق للتسجيل العام؛ الإعداد الذي تمت معاينته ما زال sender تجريبيًا `onboarding@resend.dev`، ولا تُفترض قدرة إرسال لجميع العملاء.
7. ضبط WAF وحدود مرور موزعة والتحقق من HTTPS والتدفقات على النطاق الحقيقي، ثم اختبار مالي محدود بتفويض واضح.

لذلك **الإطلاق المالي ما زال NO-GO**. لا تعرض أول عناوين الحسابات كإيداعات عامة للعملاء، ولا تفعّل التوقيع لتجاوز قائمة النواقص. حساب الإيداع المشترك للعبارة لا يدمج أرصدة العناوين ولا يلغي تكاليف التجميع.
