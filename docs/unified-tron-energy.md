# Unified TRON energy scope — preparation, not live delegation

Requirement: every energy-consuming TRON operation must obtain/verify resources for its **sender**. Current transfer scope includes (1) customer deposit-address USDT sweeps to the operating wallet and (2) operating-wallet USDT withdrawals to the approved recipient. The recipient does not need delegated energy merely to receive. BEP20 uses BNB gas, not TRON energy. This service must not rent again when existing sender resources suffice.

The existing `planTronFunding` applies resource readiness/rental planning to both transfer kinds and selects only demand-based sweeps. It waits for pending/unknown rentals, insufficient delivered resources, insufficient bandwidth/native reserve, unenforceable price cap or too-short delegation window. It is still a planner, not an executor.

`prepareTronResourceIntent` now provides one private durable intent boundary for both kinds, using the SAME `EnergyRentalIntent` table and unresolved-sender index as the legacy preparer. Payout sender is the configured operating address, net/recipient are from the bound reserved quote/operation. Sweep sender is a durable TRON assignment in an enabled, origin-verified vault; destination is fixed to operating; amount/request key come from the private trusted demand/balance planner. Missing/unready sources or unresolved signed sweeps fail closed.

Sender, destination, token amount, energy quantity, one-hour duration and maximum rental price bind the request fingerprint. Exact retry returns the same metadata; altered economics conflict. An unresolved resource request blocks another request for the same sender, including under a fresh request key. UNCERTAIN does not mean failed and does not authorize another purchase. Older withdrawal-only intents are preserved; conflicts with them fail rather than creating parallel requests. This service is for pre-signing preparation, not historical order-status readback.

Migration `20261031170000_unified_tron_energy` is prepared only. Historical withdrawal rows retain their data. New rows attach to exactly one withdrawal or sweep address; no runtime grants or external calls are introduced. Tests exercise both exact senders/transfers and uncertainty/idempotency/exclusion locally.

**Not ready live:** no paid provider create-order adapter, pre-purchase shared expense claim, provider idempotent readback, independent delivery verifier or scheduler is installed. TronZap remains a read-only client. No energy is bought/delegated by this code. Payout resource evidence validation is implemented, but live observers and a sweep dispatch resource gate still require integration. Never describe prepared intent/quoted price as delivered delegation. Other future smart-contract operations must explicitly join this unified resource workflow before being enabled.
